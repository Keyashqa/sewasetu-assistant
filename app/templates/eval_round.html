  • Real client. Each person's messages go to stock Claude Code in print mode with a small model, the way an evaluator's assistant would. Its only tools are the Sewa Setu MCP server's (8 citizen or 6 officer tools); every turn asserts that nothing else is loaded. No extra system prompt: the only guidance is the server's own instructions and tool texts.
  • Simulated people. Another model plays each person from a written card (who they are, what they know, how they talk, what they do), seeing only what that person would see. A judge marks a run invalid if the person broke their card; invalid runs are shown, not counted.
  • Their hands. Uploads and number verification happen on the portal's real pages, using only links the assistant showed in the chat. OTPs arrive on the simulated SMS gateway and are typed on the page; they never enter the chat (except where a simulated person deliberately pastes one, to test the assistant's refusal).
  • Checks are mostly the database. SQL against the portal after the conversation (status, details, audit trail, documents by hash, nothing else changed), the SMS inbox, and transcript checks (no OTPs, no password digits, no month-first dates, links shown verbatim, decisions only on the officer's instruction, audit notes in the officer's words). A model judges only a few listed items, with its evidence shown.
  • Sign-in. The harness signs each person in through the portal's real OAuth pages (OTP or the officer login) and hands the client a short-lived token. Claude Code's own sign-in to the deployed servers was checked by hand.
  • Where it ran. A fresh local copy of the portal (the full seed, the deemed-approval job off so the 700 pending cases stay pending) on the same code and configuration as the deployment. Nothing is ever run against the live portal. Only the "window has closed" person runs with the application window closed.
  • Application window. The deployment's window is extended to 31/12/2026 23:59 IST for the evaluation period (SCHEME_DEADLINE in the deployment's environment; the portal's own app.ini deadline, 31/10/2026, is unchanged). The evals run with the same setting.
  • Known limit. When the window is closed, the assistant gives the exact closed-window sentence, but sometimes adds a line about a future window.
  • 1 run per person. One run shows that a behaviour happened, not how often; small models vary from run to run. These runs use a small model as the simulated person.
  • Not tested here. An evaluator's assistant may have extra tools (shell, web) ours does not; real phones and real SMS; several officers.
  • Soft checks (reply length, emojis, optional details collected, some plain-language judgements) are reported but do not decide pass or fail.

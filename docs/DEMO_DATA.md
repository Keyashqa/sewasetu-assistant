# Demo data — local use only

`app/scripts/seed_demo_queue.py` puts clean pending applications in the officer's queue on a
**local** stack, so the officer tools have something to work on (the seed's 700 PENDING rows
are all past the 15-day SLA and have no age proof).

```bash
docker compose exec app python /app/scripts/seed_demo_queue.py --count 8
```

Run it in the `app` container: the uploads volume is read-only in `mcp`.

What it does and how its output is marked:

- Files each application through the service layer, the same path as the citizen assistant
  (`save_draft` → `issue_upload_token` → `attach_draft_document` → `submit`). No raw SQL.
- Generates each age proof as a PNG with **SAMPLE - DEMO DATA** in large dark text across the
  middle, "not a real document - generated by seed_demo_queue.py" and the generation time.
  The watermark is drawn first, the certificate fields over it.
- Records the upload with `document_uploads.source = 'demo_seed'`; `get_application` and
  `view_age_proof` show the officer that it is demo data.
- Uses only mobiles `9000001001`–`9000001099` and names starting `Demo`, picking mobiles with
  no active application.
- Refuses to run unless `PUBLIC_BASE_URL` points at `localhost` or `127.0.0.1`, and prints
  `LOCAL DEMO DATA — do not run against the deployment` every time.

**Not for the deployment.** On the public VM the queue comes from real test conversations and
the surviving seed rows; this script must not be run there.
